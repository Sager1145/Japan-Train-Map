# Hong Kong rail package 2025

`hk-2025.json` uses the same `compact-v1` package contract as the Japan and
Taiwan packages. It contains the current MTR heavy-rail network (the East Rail
and Tseung Kwan O branches are represented separately), all 11 MTR Light Rail
service routes, and the Hong Kong Island tramway.

## Identifier conventions (2025.2.0)

- Display line ids follow the Japan/Taiwan convention `{country}-{system}-{slug}`:
  `hk-mtr-ael`, `hk-mtr-eal-low`, `hk-mtr-lr-505`, `hk-tram-east`, …
- Station group ids share the solver-dataset spelling `hk-official-…`
  (e.g. `hk-official-mtr-adm`), exactly as the Taiwan package matches its
  `tw-official-…` groups.
- Station CODES (`n02_station_code`, e.g. `TML-MTR-WKS`) are persisted
  identifiers used by train stores and `station-readings-hk.json`; they keep
  the pre-normalization uppercase alias spelling and never follow display-id
  renames. `station-readings-hk.json` also resolves Taiwan-style network
  aliases `{lineId}:{stationGroupId}`.
- `country` is uppercase `HK`, `crs` is `WGS84`, and `geometrySource` carries
  `providers` / `license` / `sourceSha256` provenance like `tw-2025.json`.

## Rebuild

```bash
# 1. Route centre-lines from a raw Overpass dump of the route relations
#    ([out:json];area(3600913110)->.hk;(relation[route~"subway|light_rail|..."](area.hk););out body;>;out skel qt;):
python3 scripts/railway/build-hong-kong-track-alignments.py \
  --osm /tmp/hk-osm-rail-full.json \
  --output scripts/railway/data/hk-track-alignments.json

# 2. Tramway tracks + stop order, from a dump that keeps NODE TAGS
#    ([out:json];area(3600913110)->.hk;(relation["route"="tram"](area.hk););out body;>;out body qt;):
python3 scripts/railway/build-hong-kong-track-alignments.py --profile tram \
  --osm /tmp/hk-osm-tram-full.json \
  --output scripts/railway/data/hk-tram-alignments.json

# 3. Package + solver datasets + readings + sample store (the official tram
#    stop lists are vendored in scripts/railway/data/hk-tramways-stops-*.csv):
python3 scripts/railway/build-hong-kong-rail-package.py \
  --mtr-html /tmp/mtr-jp.html \
  --mtr-csv /tmp/mtr_lines_and_stations.csv

# 4. Precomputed sample parts:
npm run precompute:hk
```

## Official sources

- MTR official journey planner: line names, colours, station membership,
  Traditional/Simplified Chinese and English station names, and WGS84 station
  coordinates: <https://www.mtr.com.hk/en/customer/jp/index.php>
- MTR open data, `mtr_lines_and_stations.csv`: official branch direction and
  station order: <https://opendata.mtr.com.hk/data/mtr_lines_and_stations.csv>
- MTR open data, `light_rail_routes_and_stops.csv`: official Light Rail route
  and stop order: <https://opendata.mtr.com.hk/data/light_rail_routes_and_stops.csv>
- Dataset catalogue and update metadata:
  <https://data.gov.hk/en-data/dataset/mtr-data-routes-fares-barrier-free-facilities>
- Lands Department iB1000 cartographic transportation lines (`MTR` and `LR`):
  <https://data.gov.hk/en-data/dataset/hk-landsd-openmap-development-hkms-digital-b1k>
- Hong Kong Tramways open data, `summary_tram_stops_{tc,sc,en}.csv`: official
  stop codes and Traditional/Simplified Chinese and English stop names —
  <https://data.gov.hk/en-data/dataset/hktramways-hktramways-tram-stops>
- Hong Kong Tramways open data, `tramways_main_routes_*.csv`: the six numbered
  services and their termini —
  <https://data.gov.hk/en-data/dataset/hktramways-hktramways-main-routes>

High Speed Rail has only one station within Hong Kong (Hong Kong West
Kowloon), so it has no internal station interval and is not emitted as a false
cross-boundary segment.

## The tramway is carried as track, not as services

Hong Kong Tramways runs six numbered services, but all six share the same
double-track corridor along the north shore of Hong Kong Island, so a display
line per service would draw the same rails five or six times and report ~150 km
of tramway where there are ~30 km of track. The package therefore carries what
is physically distinct:

| Line | Track | Length |
| --- | --- | --- |
| `hk-tram-east` 電車東行綫 | the eastbound track, 堅尼地城 → 筲箕灣 | 13.3 km |
| `hk-tram-west` 電車西行綫 | the westbound track, 筲箕灣 → 堅尼地城 | 13.5 km |
| `hk-tram-hv` 電車跑馬地支綫 | the one-way Happy Valley loop off 堅拿道 | 3.0 km |
| `hk-tram-np` 電車北角支綫 | the 春秧街 single track, the only way in to 北角總站 | 0.8 km |

The two directions are separate lines because they are separate rails a few
metres apart with their own, separately numbered stops (odd `…E` codes
eastbound, even `…W` westbound). Each branch repeats the through-line stop it
leaves from and the one it rejoins at — 49E/52W and 65E/32W — so it shares
those station groups with the through track and is never an island in the
network graph.

Stop codes, and stop names in all three scripts, come from the operator's own
stop list; the running order and the track geometry come from the OSM tram
route relations. Every terminus is filed under the same code `T` in the
official list, so the OSM terminus codes (`KTT`, `WST`, `WMT`, `CBT`, `NPT`,
`SKT`, `HVT`) carry the identity. The three depot-only entries in the official
list — `94W` 屈地街電車廠（城西道）只落客, `97E` 西灣河電車廠 and `D` 屈地街電車廠 —
are not on any service route relation and are not emitted.

石塘咀總站, 銅鑼灣總站 and 上環（西港城）總站 sit on short terminus sidings
beside the through tracks; their platforms are projected onto the through line
at the position the official stop list gives them (a shift of 20–62 m).
北角總站 is not: it is the far end of the 春秧街 single track, so it belongs to
`hk-tram-np`.

The tramway has no operator emblem in this repository — a fabricated one would
be worse than none — so its lines fall back to the popup's line-colour swatch
beside the company label 香港電車. The line colour is the company's own
corporate green `#007549`; the six well-known route colours belong to the
services and describe none of these tracks.

## Geometry method and limitation

MTR supplies the authoritative service topology, station order, names and
colours. Track centre-lines come from OSM route relations (© OpenStreetMap
contributors, ODbL): each display line is chained from ONE route relation by
exact shared way nodes, so every line is a single continuous polyline with no
breakpoints and branches join at the true junction. An earlier hybrid that
spliced LandsD iB1000 fragments into the OSM chain produced lateral seams and
~1,300 micro-kinks across the network and was replaced by this single-source
pipeline.

For display the chained line is groomed (`build-hong-kong-track-alignments.py`):
micro-spikes (turn > 55° on sub-30 m edges) and reversal artifacts are
removed, corners are rounded with two Chaikin subdivision passes, and the
result is re-simplified at 1.5 m tolerance. Station positions are projected
onto the refined centre-line, so station anchors sit exactly on the drawn
line. It is cartographic display geometry, not engineering or cadastral
survey geometry.
