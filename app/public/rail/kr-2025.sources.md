# South Korea rail package 2025

`kr-2025.json` uses the same `compact-v1` package contract as the Japan,
Taiwan, Hong Kong and Macao packages. It contains the currently operating
South Korean network: the KTX/SRT high-speed lines, KORAIL's conventional
lines, the metropolitan electric railways, every municipal metro, the private
light-rail lines and the monorails — 78 display lines, 1,496 station rows,
about 4,262 km of drawn track.

## Identifier conventions (2025.1.0)

- Display line ids follow the Japan/Taiwan convention `kr-{slug}` where the
  slug is the Revised Romanization of the official line name:
  `kr-gyeongbuseon`, `kr-gyeongbugosokseon`, `kr-seoul-jihacheol-2hoseon`, …
- Station group ids share the solver-dataset spelling `kr-official-…`
  (e.g. `kr-official-seoul`), exactly as Taiwan matches its `tw-official-…`
  groups. Stations whose name repeats elsewhere in the country (중앙로 exists in
  대구, 부산 and 대전) get a numeric suffix so the group never merges two
  different places.
- Station CODES (`n02_station_code`, e.g. `KR-GYEONGBUSEON-SEOUL`) are
  persisted identifiers used by train stores and `station-readings-kr.json`;
  they derive from each line's `codePrefix` and never follow display-id
  renames.
- `country` is uppercase `KR`, `crs` is `WGS84`, and `geometrySource` carries
  `providers` / `license` / `sourceSha256` provenance like `tw-2025.json`.

## Rebuild

```bash
# 1. Official station records (data.go.kr, 이용허락범위 제한 없음).
#    Writes scripts/railway/data/kr/*.csv + manifest.json (sha256 per file).
python3 scripts/railway/fetch-korea-official-data.py

# 2. Track centre lines from the OpenStreetMap South Korea extract
#    (https://download.geofabrik.de/asia/south-korea-latest.osm.pbf, ODbL),
#    cached outside the repo; needs `pip install --user osmium`.
python3 scripts/railway/build-korea-track-alignments.py \
  --pbf ~/Library/Caches/japan-train-map/south-korea-latest.osm.pbf

# 3. Package + solver datasets + readings + sample store
#    (`pip install --user opencc-python-reimplemented` fills the zh_Hans column).
python3 scripts/railway/build-korea-rail-package.py

# 4. Precomputed sample parts:
npm run precompute:kr
```

## Why the track geometry is OpenStreetMap

Korea publishes no open track geometry. 국토지리정보원's 철도중심선 is distributed
through 국가공간정보포털, whose host no longer resolves at all, V-World's data API
requires an account key, and 국토정보플랫폼 (연속수치지도) requires a login and a
per-download application. KTDB's 교통망 GIS DB is application-only and not open
licensed. The centre lines therefore come from OpenStreetMap (© OpenStreetMap
contributors, ODbL) while every station identity, position, name and distance
comes from the official files above.

The extract is read from Geofabrik rather than Overpass: nationwide Overpass
queries time out on every mirror and the tiled fallback is rate limited
(429/504), while the regional `.osm.pbf` is the same data in one download.

## Geometry method and limitation

Korean OSM is tagged two different ways, so the build uses two methods:

- **Route relations** (metro, light rail, monorail, and KORAIL's metropolitan
  services) carry their ways in running order and their stops as ordered
  members. One relation is chained by exact shared node ids into a single
  continuous line — the Hong Kong method.
- **Named ways** (mainlines) have no infrastructure relation. `name=경부선`
  alone is 1,477 ways and 1,079 km of rail for a 441.7 km railway — up track,
  down track, loops and station tracks — so chaining them would triple the
  mileage. Each mainline is instead rebuilt by routing between its own
  stations over a graph of just that name's track, the Taiwan method.

Both results are groomed (spike removal above 55° on sub-30 m edges, 180°
reversal removal, two Chaikin passes, 1.5 m simplification) and split at the
projected official station positions, so station anchors sit exactly on the
drawn line. It is cartographic display geometry, not engineering or cadastral
survey geometry.

Measured against the official 영업거리: 경부선 440.6 km (official 441.7),
전라선 180.3 (180.4), 태백선 98.4 (104.1), 호남선 246.6 (252.5). The
remaining shortfalls are line ends whose last station is not the official
kilometre post.

## Display lines are railways, not services

수도권 전철 1호선 runs over 경부선 + 경인선 + 경원선 + 장항선 track, 경의·중앙선
over 경의선 + 중앙선, 수인·분당선 over 수인선 + 분당선. Publishing those brands
as display lines would draw the same rails a second and third time and double
the network mileage — the mistake the Hong Kong tramway forced us to fix — so
the package carries the physical railways and records each official service on
the stations it serves. A candidate line is also dropped when 85 % of it
already runs within 60 m of a line that is in the package.

인천공항 자기부상철도 (suspended since September 2023) is not published.

## Statistics classification

`rail-sections-kr.json` / `stations-kr.json` reuse the N02 code space
(jsonspec §2.3): institution `1` 고속철도 (경부고속선 / 호남고속선 / 수서평택고속선),
`2` 한국철도공사 일반철도, `3` municipally operated urban rail, `4` private
light rail; railway class `11`/`12` conventional heavy rail, `21` 경전철,
`31` monorail and maglev. `classifyKrSectionMask` maps them onto the shared
statistics buckets.
